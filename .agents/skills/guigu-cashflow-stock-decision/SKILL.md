# 龟龟现金流个股决策

## 定位

只做高分红现金流公司的个股/批量决策过滤，不负责完整组合阶段判断。

不要判断用户现金垫是否够、是否应该开 IC/IM、是否进入高赔率投资阶段；这些由 dashboard 和组合框架处理。若用户提供当前持仓、IC/IM 敞口、同源风险，再纳入“组合实际可加仓额度”；未提供时，只输出个股层面的仓位上限和当前价格允许仓位。

最终输出必须提醒：本 skill 的档位是龟龟框架下的过滤结果，不是投资建议、下单指令或组合阶段许可。是否执行仍需回到 dashboard、现金垫、组合风险和用户自己的决策。

## 输出边界与数据口径

所有结论都必须分离“框架过滤结果”和“投资执行决策”。`PASS-CORE` / `PASS-SMALL` 只表示通过当前漏斗进入候选或评估，不代表应该买入、加仓或马上下单。

涉及价格、财报、分红、回购、市值、股本、现金流、负债、汇率、税费的数据，必须列出来源、日期和置信度：

- 两个以上可靠来源一致：`high`
- 单一来源或公司公告单点数据：`medium`
- 口径不明、缺少关键字段、来源冲突：`low` 或 `WAIT-DATA`

穿透回报率和现金流口径必须明确：

- 证券市场：A 股 / 港股 / B 股 / 美股等，不同上市地分开算。
- 价格币种、财报币种、分红币种和必要汇率。
- 税前还是税后股息；港股、B 股、美股等必须单独说明税费假设。
- 市值、股本、回购、分红金额的口径和日期。
- 同一公司 A/H/B 多证券不能混用价格、市值和税费口径。

## 核心形态

使用漏斗过滤，不使用并列打分。

```text
候选公司
  -> 商业模式筛
  -> 穿透回报率筛
  -> 可支配现金结余筛
  -> 仓位管理筛
  -> 执行档位
```

卡在哪一关就停在哪一关。批量模式尤其不要给每家公司硬写完整研报。

## 输入模式

用户最少给：

- 公司名或代码
- 买入/加仓/批量筛选意图

尽量补充：

- 当前价格或价格区间
- 是否持有、当前仓位
- 所属账户或模块
- 现有同源风险暴露

缺少价格、财报或分红数据时，不要伪造结论；先自行检索，仍缺则输出缺口。

## 第一关：商业模式筛

先判断这家公司是否适合被当作现金流防御仓研究。使用红旗和仓位上限，不做机械评分。

逐项回答：

1. 能否看懂主营产品、客户、赚钱方式。
2. 是否依赖持续、重复、大额资本开支。
3. 赚真钱还是假钱，利润是否主要挂在应收账款。
4. 竞争还是垄断，利润是否容易被内卷侵蚀。
5. 是否有定价权，能否传导成本变化。
6. 周期性有多强，利润和股息是否可预测。

硬伤不可上限化时直接 `REJECT`：

- 看不懂业务。
- 利润主要是假钱。
- 分红明显靠借钱或融资。
- 强融资依赖。
- 周期、监管、竞争风险无法判断。

缺陷可上限化时最多 `PASS-SMALL`：

- 缺陷能说清楚。
- 风险边界能估。
- 价格极低。
- 同源风险不叠加。
- 仓位严格受限。

商业模式输出必须给“商业模式仓位上限”，例如：

- 顶级且变量少：可讨论较高上限。
- 稳定但有周期/监管/竞争约束：中等上限。
- 缺陷明显但可上限化：小仓上限。
- 不可理解或不可上限化：零仓位。

## 第二关：穿透回报率筛

只有商业模式筛通过后，才计算穿透回报率。

只计算确定穿透给股东的部分：

- 现金分红。
- 注销型回购。

不要直接计入：

- 股权激励型回购。
- 资本开支。
- 并购。
- 账上留存现金。
- 需要市场重新定价才体现的收益。

优先级：

1. 公告最低股息支付率或最低分红金额。
2. 管理层明确、多次、可核验的分红/回购承诺。
3. 5-10 年稳定派息金额或派息率。
4. 商业模式和历史数据的悲观估计。

计算前必须先统一市场、币种、税费和股本/市值口径。若用户给的是港股价格但使用 A 股财报、人民币分红或美元回购金额，必须写清楚换算方式；无法换算时输出 `WAIT-DATA`。

门槛：

- `<3%`：原则上不进现金流防御仓。
- `3%-5%`：观察或小仓。
- `5%-6%`：可进入标准仓评估。
- `6%-7%`：具备加仓基础。
- `7%+`：才考虑较高仓位，仍需通过现金流和同源风险筛。

若公司很好但当前穿透回报率不够，输出 `WAIT-PRICE`，并反推大致触发价格或市值区间。

## 第三关：可支配现金结余筛

只有穿透回报率筛通过后，才做现金流穿透。

目的不是套统一公式，而是理解真实现金进出，判断分红和回购是否有现金支撑。

至少检查：

- 经营现金流是否长期接近或高于净利润。
- 资本开支是否吃掉大部分经营现金流。
- 财务费用/利息是否显著侵蚀现金。
- 分红是否由经营现金覆盖，而不是融资覆盖。
- 现金储备扣除有息负债后是否安全。
- 应收账款是否快速膨胀。
- 投资性现金流中哪些是必要开支，哪些是一次性或可回收项目。
- A 股、港股报表科目差异是否需要逐项解释。

结论用三档，但必须写拆解过程：

- `GREEN`：经营现金流足够覆盖资本开支、财务费用和分红；净现金/现金储备安全。
- `YELLOW`：现金流能覆盖大部分分红，但资本开支、一次性项目、应收或融资结构需要解释。
- `RED`：利润主要来自应收或融资，经营现金流长期弱于分红/资本开支，疑似贷款分红。

`RED` 通常降为 `REJECT`；数据不足输出 `WAIT-DATA`。

## 第四关：仓位管理筛

按龟龟仓位管理四原则输出三层仓位：

1. 商业模式仓位上限：由商业模式稳定性和可判断性决定。
2. 当前价格允许仓位：由穿透回报率和现金流真实性决定，不得高于商业模式上限。
3. 组合实际可加仓额度：仅在用户提供组合仓位、现金垫、同源风险或 IC/IM 敞口时输出；否则标“需要组合数据”。

检查：

- 市场位置偏高、偏低还是中性；无法判断时写不确定。
- 公司属于高弹性还是低弹性。
- 当前价格是否接近多年低位或给出足够穿透回报率。
- 同源风险是否和已有持仓、地产链、白酒、金融、能源、IC/IM 名义敞口叠加。
- 若同源风险高，压低实际可加仓额度。

## 执行档位

输出且只输出以下档位之一：

- `PASS-CORE`：商业模式强、穿透回报率合格、现金流支撑真实，可进入核心现金流候选或加仓评估；不是买入建议。
- `PASS-SMALL`：可小仓观察或低上限持有，但商业模式、价格、现金流或同源风险存在约束；不是买入建议。
- `WAIT-PRICE`：公司可研究，但当前价格下穿透回报率不够。
- `WAIT-DATA`：关键数据缺失，不能判断。
- `REJECT`：商业模式、现金流、负债、分红来源或同源风险有硬伤。
