# 已有页面增量更新规范

当 `/ingest` 过程中发现已有 wiki 页面需要补充新信息时，遵循以下规则。

## 核心原则

1. **增量追加，不覆盖**：新信息追加到已有内容后面，不改写原有论述
2. **标注来源**：每条新增内容都必须标注出自哪份素材
3. **更新 version**：任何实质性修改必须更新 `version` 字段为当天日期
4. **保持引用完整**：不删除原有 `sources` 条目，只追加新条目

## 更新操作清单

### Frontmatter 更新

```yaml
# 必须更新的字段：
version: {今天日期}            # 必更

# 可能追加的字段：
sources:                       # 在数组末尾追加新来源
  - type: article              # ← 新增的来源
    title: ...
    date: ...

topic: [原有, 新增术语]        # 如有新的 glossary 术语适用

see_also: [原有, 新相关页]     # 如果新素材揭示了新关联

tags: [原有, 新标签]           # 如有新的自由标签
```

### 正文更新

根据新信息的性质选择插入位置：

| 新信息类型 | 插入位置 | 格式 |
|-----------|---------|------|
| 补充数据 | 对应章节末尾 | `**[{date} 补充]** 新数据内容 — [[source-id]]` |
| 新角度/观点 | "关键论点"或"详细说明"末尾 | 新段落，标注来源 |
| 更正旧数据 | 旧数据旁，不删旧数据 | `**[{date} 更新]** 新数据；旧数据（{旧日期}）为 xxx` |
| 相关案例 | "来源引用"或新增"案例"章节 | 引用格式 + source 链接 |

### 示例：补充数据到 entity 页

```markdown
## 关键事实

- 2026Q1 营收 1500 亿元，同比+12% — [[2026-04-report-tencent]]
- **[2026-05-14 补充]** 2026Q2 营收预期 1650 亿元，市场共识+10% — [[2026-05-14-goldman-tencent-update]]
```

### 示例：观点补充到 concept 页

```markdown
## 详细说明

（原有内容保持不动）

### 补充视角

**[2026-05-14 via [[2026-05-14-dalio-principles-ch5]]]**
达里奥对安全边际有不同的操作化定义：他建议用情景分析而非单点估值，
构建"意外发生时仍能承受"的仓位，这实质上是仓位层面的安全边际。
```

## 冲突标注格式

当新信息与已有内容矛盾时：

```markdown
## ⚠️ 观点冲突

| 维度 | 来源 A | 来源 B |
|------|--------|--------|
| 论点 | ... | ... |
| 数据支持 | ... | ... |
| 日期 | ... | ... |

**待解决**：用户需判断采信哪个观点，或标记为"open question"。
```

同时：
- 将 `status` 改为 `conflict`（如冲突严重）
- 在 `knowledge/wiki/log.md` 记录冲突

## 禁止操作

| 操作 | 原因 |
|------|------|
| 删除原有正文段落 | 破坏历史信息 |
| 覆盖 `sources` 数组 | 丢失原有溯源 |
| 修改别人的引用片段 | 引用应保持原文 |
| 不更新 `version` 直接改内容 | lint 无法追踪变更 |
| 降低 status 等级（如 active → draft） | 除非有充分理由并记录 |

## version 更新时机

| 变更类型 | 是否更新 version |
|---------|-----------------|
| 追加新数据/观点 | ✅ 是 |
| 追加新 source 条目 | ✅ 是 |
| 修正 typo/格式 | ❌ 否 |
| 补 wikilink | ❌ 否 |
| 更新 see_also | ❌ 否（除非关联关系有实质变化） |
