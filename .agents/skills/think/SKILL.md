# /think — 对话式思考沉淀

## 定位

本 skill 有两种运作方式：

1. **主动模式**：用户显式触发，Agent 做苏格拉底式追问帮助深化思考
2. **被动感知模式（始终在线）**：Agent 在任何对话中持续运行"价值雷达"，检测到高价值信号时主动提议沉淀

两者共享同一套写入流程和规范。

---

## Part A：被动感知模式（始终在线）

### 行为规则

**Agent 在所有对话中——不仅是 `/think` 被显式调用时——必须持续运行以下后台感知逻辑。这是一条 Agent 行为规范，不需要用户触发。**

### 高价值信号清单

对话中出现以下任一信号时，Agent 应在内部标记为"待沉淀候选"：

| # | 信号类型 | 识别特征 | 示例 |
|---|---------|---------|------|
| 1 | **原创推理链** | 用户串联了 ≥2 个概念得出新结论 | "如果 A 公司的护城河来自网络效应，而网络效应在下沉市场衰减，那它的估值..." |
| 2 | **与知识库矛盾/修正** | 用户表达了与已有 wiki 页面不同的观点，或用户自己说"之前的判断要改" | "我之前写的那个判断可能要修正..." |
| 3 | **认知进化** | 用户明确改变了之前的看法 | "之前觉得 X，现在觉得其实 Y" |
| 4 | **新的分析框架** | 用户提出了一种评估/思考的新方法 | "我觉得看这类公司应该用 XX 框架而不是 YY" |
| 5 | **跨领域关联** | 用户将不同 domain 的知识连接起来 | "消费降级对高端品和低端品的影响机制完全不同..." |
| 6 | **量化判断** | 用户给出了带数字的投资判断 | "我觉得合理 PE 应该在 15-18x" |
| 7 | **验证/否证** | 现实事件验证或推翻了之前的判断 | "上次说的 X 被Q2财报证实了" |
| 8 | **决策逻辑** | 用户阐述了买入/卖出/持有的具体推理 | "我打算加仓是因为..." |
| 9 | **开放式深度问题** | 对话中产生了未解答但有价值的问题 | "这引出一个问题：如果 AI 改变了..." |

### 触发阈值

**不要对每句话都提议沉淀。** 满足以下条件才提议：

- 单次对话中累计出现 **≥2 个**高价值信号，或
- 出现 **1 个信号但信息密度极高**（含量化判断 + 完整推理链），或
- 对话即将结束时（用户说再见/话题明显收束）回顾发现有价值内容

### 提议方式

在对话的自然间隙（不打断用户思路），以轻量方式提议：

```
💡 这段讨论里有几个点值得沉淀到知识库：
1. {洞察 1 的一句话概括}
2. {洞察 2 的一句话概括}
要我帮你记下来吗？（我会写入 [[target-page]] / 新建页面）
```

**提议规则**：
- 最多列 3 个点，多了让用户选
- 给出预期写入位置（已有页面还是新建）
- 用户说"不用"→ 立即停止，不再追问
- 用户说"好"/"记"/"可以" → 进入写入流程（Part C）
- 用户不理你继续聊别的 → 暂存，等下一个自然间隙再提（同一对话最多提议 2 次）
- **对话结束时的最终提议**：如果整段对话有未提议过的高价值内容，在最后一条回复中附带提议

### 不提议的情况

| 场景 | 原因 |
|------|------|
| 纯事实问答（"腾讯PE是多少"） | 没有原创思考 |
| 用户在复述已有 wiki 内容 | 已经记过了 |
| 闲聊/情绪表达 | 不属于投资知识 |
| 用户明确说过"这轮不用记" | 尊重用户意愿 |

### 感知依据（Agent 如何判断"与知识库矛盾"）

被动模式下 Agent 不需要每句话都去翻知识库。判断矛盾/修正的依据：

1. **用户自己说了**：用户明确提到"之前的判断要改"/"和我写的那个不一样"/"知识库里记的是 X，但现在..."
2. **本轮对话已加载过**：如果本轮对话中 Agent 已通过 `/query` 读取过相关页面，可以直接比对
3. **Agent 记忆**：如果 Agent 在本对话 session 内见过相关内容（如回答过相关问题）

**不做的事**：不在每句话后都主动执行 `/query` 搜索来比对——这会严重影响对话流畅度。被动感知是轻量判断，不是主动检索。

## Part B：主动模式（用户显式触发）

### 触发

- 用户说"我在想..."、"有个想法..."、"帮我想想..."
- 用户说"记一下"、"沉淀一下"
- 用户对某个问题想深入讨论（不只是要个答案）

**与 `/query` 归档的优先级**：当用户在查询过程中说"这个记下来"，由 `/query` 的归档机制处理（写入 `knowledge/wiki/analyses/`）。当用户在自由讨论中说"记一下"，由 `/think` 处理。判断标准：当前上下文是在回答事实型问题（→ query 归档）还是在讨论想法（→ think 沉淀）。

### 子模式

| 模式 | 触发条件 | 行为 |
|------|---------|------|
| **深度模式**（默认） | 正常讨论 | 完整追问流程 → 沉淀 |
| **快记模式** | 用户说"快记一下"/"直接记" | 跳过追问，直接写入用户原话 |
| **延续模式** | 对话中途用户说"这个值得记" | 回顾本轮对话，提取关键洞察写入 |

### 阶段 1：苏格拉底追问（深度模式）

**目标**：帮用户把模糊直觉变成清晰、可验证的投资论点。

追问维度（按需选择 3-5 个最有价值的，不必全问）：

| 维度 | 追问方向 | 示例 |
|------|---------|------|
| **定义清晰度** | 核心概念是否有明确定义？ | "你说的'低估'是相对什么基准？" |
| **论据支撑** | 支持这个判断的事实/数据是什么？ | "有哪些数据点让你觉得回购力度异常？" |
| **反面论证** | 最强的反对意见是什么？ | "如果这个判断错了，最可能错在哪？" |
| **边界条件** | 在什么条件下这个判断不成立？ | "如果利率超过 X%，这个逻辑还成立吗？" |
| **时间框架** | 这是短期交易还是长期持有的判断？ | "这个判断的有效期是多长？" |
| **知识库关联** | 与已有知识有何关系？ | "这和你之前写的 [[moat]] 分析是互补还是矛盾？" |
| **可验证性** | 如何在未来验证？ | "半年后用什么指标来验证这个判断？" |
| **量化程度** | 能否给出具体数字？ | "你心中的安全边际具体是多少百分比？" |

**追问规则**：
- 每轮追问 **≤ 2 个问题**
- 追问应渐进式深入，不跳跃
- 用户回答"不确定"→ 这本身值得记录为开放问题
- 追问 **3-5 轮**后主动收束："核心论点已经比较清晰了，要我帮你沉淀吗？"
- 用户说"够了"/"就这样" → 立即停止追问，进入写入

## Part C：写入流程（两种模式共用）

### 步骤 1：知识库定位

执行 `/query` 的 L1+L2 定位流程（轻量版：只跑 L1 索引扫描 + L2 topic 匹配，跳过 L3 全文搜索和候选裁剪步骤，目的仅是找到最相关的写入目标），判断写入目标：

| 情况 | 操作 |
|------|------|
| 讨论主题已有对应 wiki 页面 | → 增量追加（按 `.Codex/skills/ingest/reference/update-rules.md`） |
| 属于已有概念的延伸 | → 追加到最相关的已有页面 |
| 完全是新领域 | → 新建页面 |
| 涉及多个主题交叉 | → 新建 analysis 页面 |

### 步骤 2：确认写入方案

向用户确认（一句话，不啰嗦）：
```
"我把 {洞察概括} 写入 [[existing-page]] / 新建为 [[new-id]]，OK？"
```

### 步骤 3：执行写入

#### 来源格式（`type: dialogue`）

```yaml
sources:
  - type: dialogue
    context: "{对话主题一句话}"
    date: {今天日期}
    participants: [用户, Agent]
    trigger: "{用户原始触发话/被动捕获时为信号句}"
    rounds: 4              # 主动模式填追问轮数；被动模式填 0
    depth: refined         # refined(深度讨论) / raw(快记) / seed(种子)
```

#### 写入内容结构

```markdown
### {主题} — 对话沉淀 [{date}]

**核心论点**：{一句话总结}

**论证逻辑**：
{按讨论中整理出的逻辑顺序呈现推理链}

**关键假设**：
- {假设 1}
- {假设 2}

**待验证**：
- {验证条件 1} — 预期时间点
- {验证条件 2} — 预期时间点

**与知识库的关联**：
- 支持/补充/延伸了 [[related-page-1]]
- 与 [[related-page-2]] 存在张力

**开放问题**：
- {讨论中未解决的问题}
```

**写入内容可按实际情况精简**：不是每个字段都必须填。快记模式/被动捕获的简短洞察，只需"核心论点 + 论证逻辑 + 知识库关联"即可。

#### 写入规则

- 新建页面：按 `knowledge/schema/frontmatter.md` 填完整 frontmatter
- 追加到已有页面：按 `.Codex/skills/ingest/reference/update-rules.md` 操作
- `status` 默认 `active`（论点清晰）或 `draft`（用户说"还没想透"）
- 必须至少 1 条 `[[wikilink]]` 指向相关页面
- version 更新为今天日期

### 步骤 4：后续维护

- 更新 `knowledge/wiki/index.md`（如新建页面）
- 追加 `knowledge/wiki/log.md`：`## [YYYY-MM-DD] think | {主题简述}`
- 检查是否需要更新 `knowledge/schema/glossary.md`

### 步骤 5：输出摘要

```markdown
## 思考沉淀完成

**主题**：{讨论主题}
**触发方式**：主动(深度/快记/延续) / 被动感知

**写入位置**：
- {新建 / 追加} [[page-id]] — {一句话说明}

**论点状态**：active / draft

**后续建议**：
- {建议补充的素材/关注的数据点}
```

## 与其他 Skill 的协作

| 场景 | 协作方式 |
|------|---------|
| 讨论中需要调取知识库背景 | 内部走 `/query` 定位流程 |
| 讨论中引用了未摄入的外部素材 | 沉淀完建议用户 `/ingest` 补充 |
| 发现与已有知识矛盾 | 复用 `/ingest` 的冲突检测机制 |
| 沉淀后发现 wiki 健康度下降 | 建议用户跑 `/lint` |
| 被动捕获到验证了旧论点的信息 | 提议更新对应页面的置信度 |

## 约束

- **不替代用户判断**：追问帮助深化，最终结论必须是用户自己的
- **如实记录不确定性**：用户说"不确定"记为开放问题，不编造确定结论
- **分离事实与观点**：用户判断标"观点"，引用数据标来源
- **尊重用户节奏**：用户想停就停；被动提议被拒绝后不纠缠
- **来源诚实**：`type: dialogue` 查询时置信度天然为 medium
- **不过度打扰**：同一对话最多主动提议沉淀 2 次

## 边界情况

| 场景 | 处理方式 |
|------|---------|
| 讨论中用户引用了未摄入的外部素材 | 先沉淀，后建议 `/ingest` |
| 结论与知识库矛盾 | 标记冲突，建议判断是"认知进化"还是"需要更多证据" |
| 想法非常初步/模糊 | `status: draft`，标注"种子想法" |
| 单次讨论涉及多个不同主题 | 分别写入不同页面 |
| 用户说"这只是闲聊不用记" | 尊重意愿，关闭本轮雷达 |
| 涉及具体买卖时机 | 记录逻辑，加注"非投资建议，仅为思考记录" |
| 被动感知信号密度过高 | 优先沉淀最高价值的 3 条，其余标记为 draft 待下次讨论 |
