# XXL-JOB 调度接入

投资 API 使用 `xxl-job-core:3.4.0` 作为执行器；该依赖采用 GPL-3.0，已由项目负责人确认接受。调度中心必须独立部署在私有网络，使用独立的 `xxl_job` 数据库；不要把调度中心表混入业务库。

本地默认关闭执行器。部署环境只有在 `XXL_JOB_EXECUTOR_ENABLED=true` 且以下值全部为真实配置时才会注册：

- `XXL_JOB_ADMIN_ADDRESSES`：调度中心私网地址，例如 `http://xxl-job-admin:8080`。
- `XXL_JOB_EXECUTOR_ADDRESS`：调度中心可回调的执行器地址，端口必须与 `XXL_JOB_EXECUTOR_PORT` 一致，例如 `http://investment-api:9999`。
- `XXL_JOB_EXECUTOR_ACCESS_TOKEN`：至少 32 字符，必须与调度中心一致。

在调度中心新增以下 Bean 模式任务：

| JobHandler | 目标与 Cron（`Asia/Shanghai`） | 失败语义 |
| --- | --- | --- |
| `strategyDailyRefresh` | `0 15 0 * * ?`：在本地账本、规则、市场快照基础上重建策略评估 | 单个策略输入不足只形成解释性结果，其他策略继续 |
| `ledgerDailySnapshot` | `0 35 0 * * ?`：在策略评估后，为每位有账务事实的用户生成当日账本版本快照 | 每位用户使用独立新事务；失败不会回滚其他用户快照，任务最终标记失败供运维重试 |

两项任务共同配置：执行器 `investment-api-executor`；路由策略为单实例“第一个”或多实例“一致性哈希”；阻塞策略为“单机串行”；失败重试设为 0，由运维核查日志后手动重试。

策略任务只读取已确认的本地账本、规则和市场快照后生成策略评估；不会访问券商 API、不会下单，也不会因缺失行情补造数据。若任一策略缺失输入，它会记录该策略结果，其他策略仍继续执行。

快照任务只处理已存在的不可变账本事实：快照正文仅写入私有、服务端加密的对象存储，元数据和生成动作分别落入业务表与审计日志；不会访问券商 API，不会覆盖、删除、回滚或恢复任何现有账务事实。
