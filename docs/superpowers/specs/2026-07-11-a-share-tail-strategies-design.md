# A 股尾盘短线四策略设计

## 目标

在既有 `modules/short_term/` 模块中新增独立的 `tail` 策略入口。它提供四个使用 A 股日线 OHLCV 数据的尾盘买入策略、最多三只实际持仓的组合执行器，以及可在 Windows + 通达信环境运行的历史回测程序。

本设计不构成投资建议，也不把公开页面的历史结果表述为改造后策略的结果。

## 已确认的约束

- 标的：A 股股票；扫描流动性合格的用户提供股票池，任一交易日实际持仓不超过 3 只。
- 交易时点：信号在尾盘形成并以当日收盘价近似买入；买入后遵守 T+1，次日起可按策略独立退出。
- 持有期：每个策略独立止盈、止损和技术退出，但最长持有 10 个交易日。
- 运行环境：Windows + 通达信。Mac 只执行纯逻辑测试，不拉取通达信行情，也不运行真实回测。
- 成本：买卖佣金双边万分之一、免最低佣金；卖出印花税万分之五、单边滑点万分之五。后三项均可由 CLI 覆盖。
- Git：只允许本地 `add` 与 `commit`，禁止 `push`。

## 四个策略

所有策略先排除数据不足、零成交额、当日不可交易（以日线价格无法形成有效成交近似）的标的，再用内部评分排序，最多选入三只。

1. `steady_momentum`：10 日类夏普收益为正、收盘在短均线之上，近 10 日振幅与成交额波动较低；以趋势质量、低振幅和量能稳定度评分。退出为 -4% 止损、+8% 止盈、收盘跌破 MA5 或第 10 日尾盘。
2. `trend_confirmation`：市场指数 MA20 > MA60 时才允许新开仓；个股满足 EMA20 > EMA60、MACD 多头、RSI(14) 处于 45–75、收盘高于布林中轨。以 MACD 柱、20 日动量和 RSI 评分。退出为 -5% 止损、+10% 止盈、MACD 转弱或第 10 日尾盘。
3. `macd_divergence`：市场指数 MA20 > MA60 时才允许新开仓；个股最近局部低点低于前一局部低点但 MACD DIF 高于前一局部低点，并以阳线/收盘突破前一日高点确认。以背驰幅度、确认强度和量能评分。退出为 -5% 止损、+8% 止盈、收盘跌破 MA5 或第 10 日尾盘。
4. `cup_handle_breakout`：近期存在前段上涨，之后形成杯底和位于杯上半部的短柄；柄期成交额低于杯期成交额，尾盘收盘突破柄部高点。以突破幅度、柄部收缩和量能确认评分。退出为 -6% 止损、+12% 止盈、收盘跌破柄部低点或第 10 日尾盘。

## 架构

- `modules/short_term/strategies/tail.py`：日线指标、四个纯信号函数、策略定义和实时扫描 CLI。
- `modules/short_term/backtest_tail.py`：通用的日线回放引擎、三仓组合状态、交易成本、成交近似、指标统计、文件输出 CLI。
- `modules/short_term/backtest_cache.py`：复用现有 SQLite 日线缓存和 `DailyBar`，不复制缓存层。
- `modules/short_term/registry.py`：注册 `tail` 策略；`invest.py` 新增 `short backtest-tail` 路由。
- `tools/dashboard/test_tail_strategies.py`：纯 Python 测试，不依赖通达信。
- `knowledge/wiki/sources/`：四份来源页；`knowledge/wiki/portfolios/`：一份策略总页；`knowledge/wiki/index.md` 与 `knowledge/wiki/log.md` 更新索引与操作日志。
- `docs/superpowers/plans/`：实现计划；`modules/short_term/README.md`：Windows 执行说明。

## 数据、成交与回测

- `--symbols-file` 为必填文本文件，每行一个通达信代码；程序不会假定通达信接口可可靠枚举历史全市场。
- 回测通过既有通达信客户端拉取未复权 `Open/High/Low/Close/Volume/Amount` 并缓存。调用前必须额外拉取足够的指标预热期。
- 尾盘入场价格近似为 `close × (1 + buy_slippage)`，买入佣金为成交额 × 0.0001。
- 持仓从下一交易日才可卖。若开盘已越过止盈或止损价，按开盘成交；否则日内触及单一阈值按阈值成交；同一根日 K 同时触及止盈和止损时一律按止损成交；技术或最长持有退出按收盘成交。
- 卖出佣金为成交额 × 0.0001，卖出印花税为成交额 × 0.0005，卖出滑点向下调整成交价。
- 报告必须包含执行假设、数据缺口、涨跌停及日线先后顺序无法重建等限制。
- 由于通达信日线与用户提供的当前股票池不能完整重建历史 ST、停牌、退市、指数成分和涨跌停制度变化，回测报告必须把这些列为未消除的偏差来源。

## 输出与失败处理

- 输出目录：`data/short-term/tail-backtests/<开始日期>_<结束日期>/<策略ID>/`。
- 产物：`trades.csv`、`report.json`、`report.md`；报告包含交易次数、胜率、平均盈利、平均亏损、盈亏比、凯利值、最大回撤、持仓上限和逐笔交易。
- 未安装/无法连接通达信、股票池文件为空、日期非法、指标预热不足、日线字段缺失时，命令退出并给出中文可操作错误。
- 实时扫描和回测均不执行券商下单。

## 验证范围

- 在 Mac 上测试所有纯函数：指标、四类信号、候选排序、最多三仓、T+1、止盈止损同日冲突、费用和凯利计算、CSV/JSON/Markdown 输出。
- 在 Mac 上不调用通达信，也不将未执行的 Windows 历史回测描述为通过。
- Windows 用户按 README 准备通达信、股票池和日期后执行实际扫描/回测。
