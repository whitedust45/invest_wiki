# 旧 Dashboard 到微信小程序的功能等价矩阵

状态：核心等价能力已完成；发布前仍须完成真实微信、域名与真机门禁  
范围：`apps/dashboard/app.js` 的个人投资账本功能，迁移至 `new_project/apps/miniprogram` 与 Java 服务端。  
核心边界：账本事实不可变、所有金额为原币种 `*_cent` 整数、CNY/USD 独立核算、不建立物理外键、不以浏览器本地存储作为事实源。

|---|---|---|

| 资产账户树、持仓排行、成本/未实现损益 | 服务端按原币种投影；仅在估值完整、精度可表达时展示，否则显式未估值 | 已迁移 |

## 恢复的已确认安全边界

恢复不能成为“将当前数据库回写为旧状态”的覆盖操作：这会破坏账本的不可变性、冲正链和既有审计记录。因此实现固定为以下规则：

1. 快照来自同一 owner 的 JSON 账本事实导出，正文位于私有、服务端加密的对象存储；下载及恢复前均校验 owner、对象键、状态和 SHA-256。
2. 恢复前先锁住 `ledger_state`，再确认该 owner 没有任何账户和账务事实。任一条件不满足，返回 `409 SNAPSHOT_RESTORE_REJECTED`，且不会写入任何记录。
3. 通过校验后，服务端使用新的语义化 ULID 写入账户、交易、分录及交易明细；所有恢复交易统一标为 `IMPORT`，并指向快照工件。旧 ID 仅作为快照历史，不会与新账本混用。
4. 恢复不会导入或覆盖行情主数据、策略规则、评估结果或对象存储密钥；快照引用的标的必须已存在于本地受管主数据中。缺失时整体拒绝。
5. 已有账本的纠偏只能通过新的追加事实、冲正与替代链完成；快照可以下载核对，但不能用于“回滚”。

快照保留策略目前为永久保留，直到产品定义出合规的保留/删除期限；这项运行策略为 **TBD**，不影响恢复的不可变性边界。
